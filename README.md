# CRM рекрутингу

Внутрішня CRM для команди рекрутерів, яка закриває вакансії підприємств Львова (здебільшого лінійні посади).

**Головний сценарій:** рекрутер відкриває вакансію, бачить усіх кандидатів на неї і веде кожного по статусах: від «Новий» до «Вийшов на роботу» або «Відмова».

## Як працює

1. Ми купуємо й публікуємо вакансію на Work.ua (наприклад, «Комірник») і створюємо її в CRM з посиланням на Work.ua.
2. Кандидати на вакансію в CRM поділені на **три розділи**:
   - **Відгуки**: люди, які самі відгукнулися на вакансію на Work.ua;
   - **Рекомендовані Work.ua**: кандидати, яких запропонувала платформа;
   - **Підібрані рекрутером**: люди, яких рекрутер сам знайшов у базі резюме. Їх додають кнопкою «+ Кандидат», вставивши посилання на резюме.
3. Рекрутер працює з кожною людиною: дзвонить, пропонує вакансію, запрошує на співбесіду й відмічає результат статусом.

### Статуси

Статуси взяті з робочої таблиці команди й доповнені етапами співбесіди:

| В роботі | Закриті |
|---|---|
| Зателефонувати (новий) | Вийшов на роботу |
| Не додзвонилися | Резерв |
| Написали у Viber | Не підходить |
| Передзвонити | Не актуально |
| Думає | |
| Запрошено на співбесіду (з датою і часом) | |
| Не прийшов на співбесіду | |
| Пройшов співбесіду | |

Статуси задані в `recruiting/models.py` (`Application.Stage`) і легко змінюються під процес.

## Що вміє зараз

- **Список вакансій.** Для кожної вакансії видно кількість кандидатів у кожному розділі (і скільки з них нових), кількість співбесід і скільки людей вийшло з потрібної кількості. Є фільтри «Відкриті / На паузі / Закриті» та «Лише мої».
- **Сторінка вакансії.** Три розділи з лічильниками, усередині кожного — вкладки статусів і пошук за ім'ям, телефоном або приміткою. Таблиця виглядає як ваш аркуш: Ім'я (з посиланням на Work.ua), Вік, Контакт (+ кнопка Viber), Район, Статус, Примітка.
  - Статус змінюється прямо в таблиці. Якщо вибрати «Запрошено на співбесіду», CRM попросить вказати дату.
  - **Примітку** редагують прямо в рядку, як клітинку в Google Таблиці: вона зберігається, щойно вийти з поля (або натиснути Enter).
- **Картка кандидата.** Кнопки швидкого результату дзвінка («Не додзвонилися», «Написали у Viber», «Передзвонити», «Думає», «Запрошено на співбесіду», «Не підходить», «Не актуально»). Також є контакти, кнопка «Написати у Viber», примітка, резюме й повна історія (хто, коли і що змінив). Кандидата можна перенести в інший розділ і побачити, на які ще вакансії він подавався.
- **Додавання кандидата.** Вставте посилання з Work.ua, ім'я, вік, телефон, район і примітку — як новий рядок у таблиці. Розділ визначається за посиланням автоматично: `…/my/applicants/…` → «Відгуки», `…/my/recommended/…` → «Рекомендовані», `…/resumes/…` → «Підібрані». Кнопка «Зберегти і додати ще» дає вносити людей підряд.
- **Імпорт з Google Таблиці.** На сторінці вакансії є кнопка «Імпорт з таблиці». У Google Таблиці відкрийте вкладку вакансії → Файл → Завантажити → CSV і завантажте файл у CRM. Колонки Лінк, Ім'я, Вік, Контакт, Район, Статус, Примітка розпізнаються автоматично, статуси перетворюються на статуси CRM, порожні рядки пропускаються, повторний імпорт не дублює людей.
- **Без дублікатів.** Кандидата шукають за посиланням з Work.ua, телефоном (у будь-якому форматі: `067…`, `+38 (067)…`) або email. Якщо така людина вже є, її додають на вакансію як наявну. Коли рекомендований кандидат сам відгукується, його переносять у «Відгуки», а статус зберігається.
- **Адмінка** (`/admin/`). Тут ведуть підприємства-замовники й користувачів (рекрутерів).

## Інтеграція з Work.ua

**Стан:** логіка синхронізації готова й покрита тестами. Не вистачає лише доступу до API Work.ua.

У Work.ua **немає публічного документованого API** для роботодавців. ATS-системи (PeopleForce, HURMA та інші) отримують відгуки через партнерський доступ, який надає сам Work.ua. Що потрібно зробити:

1. Звернутися до Work.ua (менеджер облікового запису роботодавця або підтримка). Запитати доступ до API для отримання відгуків і рекомендованих кандидатів на свої вакансії для власної CRM і документацію до нього.
2. Після отримання доступу реалізувати `WorkUaApiClient.list_responses()` і `list_recommended()` у `recruiting/integrations/workua.py`. Це лише перетворення відповіді API на `WorkUaCandidate`. Решта (розподіл по розділах, дедуплікація, створення кандидатів, історія) вже працює.
3. Задати змінні `WORKUA_BACKEND=api`, `WORKUA_API_BASE_URL`, `WORKUA_LOGIN`, `WORKUA_PASSWORD`.

Як це працюватиме:

- У вакансії вказується її ID або посилання на Work.ua (`https://www.work.ua/jobs/1234567/`).
- Кнопка «⟳ Оновити з Work.ua» на сторінці вакансії підтягує нові відгуки (у розділ «Відгуки») і рекомендованих кандидатів (у розділ «Рекомендовані Work.ua»).
- Для автоматичної синхронізації команду `python manage.py sync_workua` ставлять у cron, наприклад раз на 15–30 хвилин.

**Поки доступу немає,** кандидатів додають кнопкою «+ Кандидат» на сторінці вакансії: вибирають розділ і вставляють посилання на резюме з Work.ua.

## Технології

Python 3.13, Django 5.2, PostgreSQL (у продакшні) або SQLite (локально), серверні шаблони без JS-фреймворків. Інтерфейс українською, часовий пояс — Київ.

## Запуск на своєму комп'ютері (щоб спробувати)

Потрібен лише [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows / macOS) — встановіть і запустіть його.

1. Завантажте код один раз через `git` (тоді оновлення — одним кліком, див. нижче). У Терміналі:
   ```bash
   cd ~
   git clone https://github.com/hrynchukk-cmyk/crm_recruitment.git
   cd crm_recruitment
   ```
   Код з'явиться в папці `crm_recruitment` у вашій домашній теці. Якщо macOS запропонує встановити «інструменти розробника командного рядка» — погодьтеся, це і є `git`.
2. У папці проєкту скопіюйте файл `.env.example` у `.env` і відкрийте його в текстовому редакторі (`cp .env.example .env && open -e .env`). Поміняйте `DJANGO_SECRET_KEY` (будь-який довгий випадковий рядок), `DJANGO_SUPERUSER_PASSWORD` (ваш пароль для входу) і `POSTGRES_PASSWORD`.
3. У терміналі в папці проєкту:
   ```bash
   docker compose up -d --build
   ```
   Перший запуск триває кілька хвилин.
4. Відкрийте http://localhost:8100 і увійдіть як `admin` з паролем із `.env`.

**Ізоляція від інших проєктів у Docker.** CRM — окремий проєкт Docker Compose з ім'ям `crm_recruitment`. Її контейнери (`crm_recruitment-web-1`, `crm_recruitment-db-1`), мережа й том з базою мають власні імена й не торкаються інших проєктів. База не відкриває порт назовні. CRM доступна лише з цього комп'ютера на порту 8100. Якщо цей порт уже зайнятий, змініть `CRM_PORT` у `.env`.

- **Зупинити:** `docker compose down`, виконане в папці CRM (зупиняє лише CRM). Дані зберігаються й будуть на місці після наступного `docker compose up -d`.
- **Не запускайте** `docker compose down -v`: прапорець `-v` видаляє базу CRM разом з даними.

### Оновлення до нової версії

Двічі клацніть файл **`update.command`** у папці `crm_recruitment` (Finder), або в Терміналі в цій папці:
```bash
./update.command
```
Скрипт завантажить оновлення з GitHub (`git pull`) і перезапустить CRM (`docker compose up -d --build`). Дані й файл `.env` залишаються як були. Docker Desktop має бути запущений.

### Перші кроки в CRM

1. **«+ Нова вакансія»**: назва посади, підприємство (нове можна вписати прямо у формі) і посилання на вакансію на Work.ua.
2. На сторінці вакансії натисніть **«Імпорт з таблиці»** і завантажте CSV з відповідної вкладки Google Таблиці. Або додавайте людей кнопкою **«+ Кандидат»**.
3. Акаунти для рекрутерів створюються в **Адмінка → Користувачі → Додати користувача**.

## Розгортання на сервері (для всієї команди)

Щоб CRM була доступна рекрутерам з будь-якого комп'ютера чи телефона, її розміщують на сервері з HTTPS. Є два варіанти:

**A. Хмарний хостинг з Docker (Render, Railway тощо)** — без адміністрування сервера.
Створіть сервіс із цього репозиторію (він збирається з `Dockerfile`), додайте базу PostgreSQL і задайте змінні:

| Змінна | Значення |
|---|---|
| `DATABASE_URL` | видає хостинг для бази PostgreSQL |
| `DJANGO_SECRET_KEY` | довгий випадковий рядок |
| `DJANGO_ALLOWED_HOSTS` | домен сервісу, напр. `crm-xxxx.onrender.com` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://` + той самий домен |
| `DJANGO_SECURE_COOKIES` | `1` |
| `DJANGO_SUPERUSER_USERNAME` / `DJANGO_SUPERUSER_PASSWORD` | перший адміністратор, створюється автоматично |

Порт (`PORT`) хостинг задає сам.

**B. Власний VPS.** Встановіть Docker і зробіть усе як у розділі вище. У `.env` вкажіть свій домен у `DJANGO_ALLOWED_HOSTS` і `DJANGO_CSRF_TRUSTED_ORIGINS` та `DJANGO_SECURE_COOKIES=1`. Перед застосунком поставте HTTPS-проксі (наприклад, Caddy).

**Резервні копії бази:** на хостингу вмикаються в налаштуваннях PostgreSQL. На VPS використовуйте `docker compose exec db pg_dump -U crm crm > backup.sql`.

## Для розробників

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export DJANGO_DEBUG=1
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo   # демо-дані + користувач admin/admin (лише з DJANGO_DEBUG=1)
.venv/bin/python manage.py runserver
```

Тести: `DJANGO_DEBUG=1 .venv/bin/python manage.py test`

## Структура

```

recruiting/services.py       зміна статусу, нотатки, додавання кандидата (з дедуплікацією)
recruiting/integrations/     інтеграція з Work.ua
recruiting/views.py          сторінки рекрутера
recruiting/importer.py       імпорт CSV з Google Таблиці
recruiting/management/       команди sync_workua, ensure_admin, seed_demo
```
