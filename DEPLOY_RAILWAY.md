# Розгортання CRM на Railway

[Railway](https://railway.com) запускає CRM з того самого `Dockerfile`, що й локально. У хмарі працюватимуть три частини:

| Сервіс | Що робить |
|---|---|
| **web** | сайт CRM (адреса на кшталт `https://crm-xxxx.up.railway.app`) |
| **worker** | фонова синхронізація з Work.ua кожні 15 хв (той самий код, інша команда запуску) |
| **Postgres** | база даних |

Потрібен тариф Hobby: за даними Railway, $5 на місяць, які вже включають $5 використання. Для невеликої CRM зазвичай виходить близько $5–8 на місяць. Перевірте актуальні ціни на [railway.com/pricing](https://railway.com/pricing).

Назви кнопок нижче можуть трохи відрізнятися: Railway час від часу оновлює інтерфейс.

---

## 1. Акаунт і проєкт

1. Зайдіть на [railway.com](https://railway.com) → **Login → Continue with GitHub**. Увійдіть акаунтом, якому належить репозиторій `crm_recruitment`.
2. Оберіть тариф **Hobby** і додайте картку.
3. **New Project → Deploy from GitHub repo** → дозвольте Railway доступ до репозиторію `crm_recruitment` → виберіть його.
   Railway почне збірку з `Dockerfile`. Перший запуск може впасти, бо ще немає бази. Це нормально.

## 2. База даних

На полотні проєкту: **+ Create** (або **New**) → **Database** → **PostgreSQL**.

## 3. Змінні сайту (сервіс web)

1. Клацніть сервіс з кодом (для зручності перейменуйте його на `web`) → вкладка **Variables** → **Raw Editor**.
2. Вставте й замініть значення у `<…>`:

   ```
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   PORT=8080
   DJANGO_SECRET_KEY=<довгий випадковий рядок>
   DJANGO_SUPERUSER_USERNAME=admin
   DJANGO_SUPERUSER_PASSWORD=<надійний пароль адміністратора>
   WORKUA_BACKEND=api
   WORKUA_LOGIN=<email кабінету Work.ua>
   WORKUA_PASSWORD=<пароль кабінету Work.ua>
   WORKUA_SYNC_MINUTES=15
   ```

   - `DJANGO_SECRET_KEY` згенеруйте в Терміналі на Mac:
     ```bash
     openssl rand -hex 32
     ```
   - `${{Postgres.DATABASE_URL}}` пишеться саме так. Railway сам підставить адресу бази. Якщо ваша база називається інакше, ніж `Postgres`, змініть назву в дужках.
   - Поки немає пароля Work.ua, поставте `WORKUA_BACKEND=disabled`. Решта працюватиме.
3. Збережіть: **Update Variables**.

`DJANGO_ALLOWED_HOSTS` і `DJANGO_CSRF_TRUSTED_ORIGINS` задавати не треба: CRM сама бере домен, який видає Railway, і вмикає HTTPS.

## 4. Адреса сайту

1. Сервіс **web** → **Settings** → **Networking** → **Generate Domain**. Якщо Railway спитає порт, вкажіть **8080**.
2. Там само в **Settings**:
   - **Healthcheck Path:** `/healthz/` (необов'язково, але корисно: Railway не перемкне на нову версію, доки вона не запуститься);
   - перевірте, що автоматичне розгортання з гілки **main** увімкнене. Тоді кожен злитий pull request сам оновлюватиме хмарну CRM.
3. Дочекайтеся статусу **Active** і відкрийте згенеровану адресу. Увійдіть як `admin` з паролем з `DJANGO_SUPERUSER_PASSWORD`.

## 5. Фонова синхронізація з Work.ua (сервіс worker)

1. На полотні проєкту: **+ Create** → **GitHub Repo** → знову `crm_recruitment`. Перейменуйте сервіс на `worker`.
2. **Settings** → **Deploy** → **Custom Start Command**:
   ```
   python manage.py sync_workua --loop
   ```
3. **Variables** → **Raw Editor** → вставте ті самі змінні, що й для web, крім `PORT`.
4. Домен цьому сервісу **не** генеруйте: йому не потрібен вхід з інтернету.
5. У **Deployments → View logs** має з'явитися «Фонова синхронізація з Work.ua: кожні 15 хв.»

## 6. Рекрутери

У CRM: **Команда → + Додати користувача** → роль **Рекрутер** → передайте людині адресу сайту, логін і пароль.

Сайт відкритий з інтернету й містить персональні дані кандидатів:
- давайте лише надійні паролі;
- вимикайте доступ людям, які більше не працюють з CRM («Команда» → користувач → прибрати «Доступ до CRM увімкнено»).

## Перенести дані з комп'ютера (необов'язково)

За замовчуванням хмарна CRM починає з порожньої бази. Щоб перенести ваші поточні вакансії, кандидатів і користувачів:

> ⚠️ Це **замінить** усе, що вже є в хмарній базі. Робіть це на початку, поки рекрутери нічого не внесли.

1. Резервна копія локальної бази (Docker Desktop має бути запущений):
   ```bash
   cd ~/crm_recruitment && docker compose exec -T db pg_dump -U crm --no-owner --no-acl --clean --if-exists crm > ~/Desktop/crm-backup.sql
   ```
2. У Railway: сервіс **Postgres** → **Variables** → скопіюйте значення **`DATABASE_PUBLIC_URL`**.
3. Відновлення в хмарну базу. Вставте скопійоване значення замість `ПУБЛІЧНИЙ_URL`, у лапках:
   ```bash
   docker run --rm -i postgres:16 psql "ПУБЛІЧНИЙ_URL" < ~/Desktop/crm-backup.sql
   ```
4. У Railway перезапустіть сервіс **web**: **Deployments → … → Restart**.

Після перенесення у хмарі будуть ті самі користувачі й паролі, що й на вашому комп'ютері: `admin` входить своїм локальним паролем. Резервну копію `crm-backup.sql` з робочого столу після цього видаліть: у ній персональні дані кандидатів.

## Якщо щось не працює

- **Сервіс web падає при запуску:**
  - відкрийте **Deployments → View logs**;
  - найчастіше причина в тому, що не задано `DJANGO_SECRET_KEY` або `DATABASE_URL`.
- **«Bad Request (400)» на сайті:** домен згенеровано вже після запуску. Перезапустіть сервіс web, щоб CRM підхопила адресу.
- **Синхронізація з Work.ua:**
  - стан видно у вкладці «Вакансії» під заголовком, а також у логах сервісу worker;
  - після зміни `WORKUA_*` перезапустіть обидва сервіси.
